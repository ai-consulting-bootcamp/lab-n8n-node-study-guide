## Ticket-workflow variations

The three Edit Fields nodes are the same node type and count only once. The fixture Set uses JSON Output with the supplied four fields. Structured Output maps those four fields, adds accepted status and category-derived queue, and omits unlisted fields. Rejection Output retains ticket_id (or null) plus rejected status and a reason. IF uses a strict Boolean expression with guarded string access; fields with unsupported types/values are rejected rather than silently converted. The validation expression is fully visible in [workflow.json](workflow.json).

Ticket ID must be a string matching `T-<digits>`; category must be portal, monster, psychic, or environmental; message must be a nonblank string; priority must be low, medium, or high. This validates structure and allowed values, not whether a complaint is true. Extra fields are not output by the final mappings.
